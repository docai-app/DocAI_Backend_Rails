# Talk Lab Speaking與學生自創建學習包方案說明

## 1. 方案目標

本方案希望在現有 AIEnglish 作業體系上增加兩項能力：

1. 增加一種新的口語對話作業：`talk_lab_speaking`。
2. 允許學生透過系統提供的學習主題，自主生成一組有順序的練習任務，也就是 Assignment Package。

最終效果是：老師仍然可以像現在一樣佈置作業；同時，學生也可以在前端選擇一個學習主題，透過一次 AI 對話生成專屬練習包，然後按順序完成裏面的多個作業。

## 2. 新口語作業：Talk Lab Speaking

`talk_lab_speaking` 是一種即時對話型口語作業。

學生進入作業後，會和AI進行多輪RTC對話。前端會根據作業內容整理出對話提示，讓AI知道本次對話的主題、目標和要求。

學生手動結束對話後，系統會保存：

-學生和AI的文字對話記錄。
- 學生每一輪發言的錄音連結。
- AI每一輪回覆的錄音連結。
-對話時長、輪次等基礎資訊。

之後系統會把對話內容交給 Dify 評分流程，生成分數、評價和報告。這個流程和現有 essay、speaking conversation 的處理方式類似，評分會在後台自動完成，不需要學生等待頁面一直打開。

## 3. 學生自創建學習包

目前學生不能自己創建 Assignment。新方案不是直接開放學生創建普通作業，而是透過「學習模板」來控制入口。

系統管理員先在後台配置多個學習模板，例如：

- Travel
- Job Interview
- Daily Conversation
- IELTS Speaking Practice

每個模板會包含標題、描述、學習目標、前端對話提示材料等信息。

學生在前端看到這些模板後，選擇其中一個進入 AI 對話頁面。學生和 AI 對話結束後，系統會根據這次對話生成一個 Assignment Package。

Assignment Package可理解為一個「學習包」，裡面包含多個按順序排列的作業。例如：

1. Talk Lab Speaking：聊一次旅行經歷。
2. Essay：寫一篇關於旅行計劃的短文。
3. Sentence Puzzle：完成相關句子練習。

具體生成哪些作業，由 Dify 根據學生對話內容決定。系統只會創建 AIEnglish 已支持的作業類型；如果 Dify 返回了不支持的類型，系統會自動跳過，不影響其他正常作業生成。

## 4. 學習包完成規則

Assignment Package內的作業必須按順序完成。

學生完成第一個作業後，第二個作業才會開放；完成第二個後，第三個才會開放，以此類推。

當前階段的完成規則採用比較寬鬆的方式：只要學生已經提交了對應作業，就算完成，不要求評分一定成功。這樣可以避免因為某一次 AI 評分失敗，導致學生無法繼續完成後面的練習。

後續如果業務希望改成「必須評分成功才算完成」，系統會把這個判斷集中在一個統一規則裡，方便調整，不需要大範圍改動。

## 5. 展示與訪問規則

學生端會在現有「我的作業」入口中同時看到兩類內容：

- 老師佈置的作業。
-學生自己生成但尚未完成的 Assignment Package。

當一個Assignment Package全部完成後，它不會再出現在「我的作業」待完成列表中，但學生可以在新的歷史紀錄頁面查看所有已生成過的學習包和完成摘要。

訪問權限設計如下：

- 学生只能查看和完成自己的 Assignment Package（作業套件）。
- 管理員可以查看 Assignment Package，用於客服、審核和問題排查。
- 老師暫時不管理學生自己生成的 Assignment Package。
- 如果學生知道某個學習包內作業的 code，也不能跳過順序直接進入未解鎖的作業。

## 6. 刪除規則

為了避免誤刪學習記錄，學生不能隨意刪除 Assignment Package。

規則如下：

- 如果 Assignment Package 生成失敗，學生可以自行刪除。
- 如果 Assignment Package 正在生成、已開始完成、已完成，學生不能刪除。
- 管理員可以刪除，用於處理異常數據或客服場景。

這樣可以避免學生刪除已經有學習進度或提交記錄的內容。

## 7. 管理員後台

管理員需要新增學習模板管理能力。

管理員可以維護：

- 模版標題。
- 模版描述。
- 學習目標。
- 模版狀態，例如啟用、停用。
- 前端生成AI對話提示所需的材料。
- 調用 Dify 生成學習包所需的配置。

如果學生生成學習包失敗，管理員可以查看失敗原因，也可以在後台重試。

## 8. 後續擴展預留

本階段先不做學習者資料和使用次數限制，但方案會預留擴展空間。

後續可以支持：

- 一個帳號下添加多個學習者。
- 用戶在前端切換學習者。
- 不同學習者看到各自的学习包。
- 限制每個學生每天、每月或總共可以生成多少個學習包。
-根據學校、帳號或訂閱計劃設置不同限制。

當前階段學生生成學習包不消耗額度，也不影響老師或學校的配額。

## 9. 實施階段

### 第一階段：新增 Talk Lab Speaking 作業

目標：

- 支持老師創建 `talk_lab_speaking` 作業。
- 支持學生完成 RTC 對話並提交。
- 保存文字對話和每一輪錄音鏈接。
-後台自動調用 Dify 生成評分和報告。

### 第二階段：新增學習模板與學習包生成

目標：

- 管理員可以配置學習模板。
- 學生可以選擇模板進入 AI 對話。
- 對話結束後，系統生成 Assignment Package。
- Package內可以包含多個不同類型的作業。
- 生成失敗時，學生可以重新開始，管理員可以查看和重試。

### 第三階段：學習包進度與列表整合

目標：

- 學習包內作業按順序解鎖。
- “我的作業”同時展示老師佈置的作業和未完成學習包。
- 完成全部作業後，學習包進入歷史記錄。
- 學生只能刪除生成失敗的學習包。

### 第四階段：後續擴展

目標：

- 支持多個學習者資料。
- 支持使用次數限制。
- 增加更完整的統計、審核和運營能力。

## 10. 方案收益

這個方案的主要價值是：

- 保留現有老師佈置作業流程，不破壞已有功能。
- 讓學生可以自主生成個性化練習內容。
- 通過學習模板控制入口，避免學生隨意創建不可控內容。
- 通過順序解鎖，讓練習更有路徑感和完成感。
- 通過後台異步評分，減少前端等待壓力。
- 為後續學習者資料、使用次數限制和運營統計預留空間。

整體上，這是一種在現有 Assignment 體系上逐步擴展的方案，既能滿足當前 Talk Lab 和學生自創建學習包需求，也能為後續個性化學習路徑打基礎。
