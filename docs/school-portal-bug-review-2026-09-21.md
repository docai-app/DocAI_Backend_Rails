## Findings and fixes

1. **Cross-school assignment reads (backend):** creator membership alone allowed a teacher assigned to two schools to expose the other school's explicitly owned assignments. Two added isolation cases failed before the fix. `assignments_scope` now intersects creator membership with the assignment's school academic year. This shared scope governs lists, detail, submissions and statistics; snapshot recent rows and counts now use the same scope. Both API aliases are covered. For legacy assignments with no academic year, the compatibility fallback is allowed only when the creator has membership in this school and no membership in another school. Ambiguous legacy assignments are hidden from the school portal until their ownership is established; records and teachers' normal teaching access are not modified.
2. **Historical credential metadata (backend):** audit-log list filtered credential keys, but snapshot logs returned raw metadata. Snapshot now filters the same `password`, `password_confirmation` and `default_password_label` keys. Tests use only synthetic values; no historical records are rewritten.
3. **Plus-address login (frontend):** the old email regex rejected legal addresses such as `teacher+school@example.test` before reaching the server. Basic format checking now matches Devise's non-space/non-@ local/domain structure; the server still authenticates credentials. Browser regression reproduced the previous rejection; Rails also accepts a real synthetic plus-address owner login.
4. **Uncertain reset (frontend):** a timeout/no response or 5xx could leave the reset confirmation enabled. These outcomes now require manual verification before another operation; no automatic repeat. 401/403/404 also block reuse of that confirmation.
5. **Confirmed reset followed by failed list refresh (frontend):** a bound SWR revalidation can resolve with cached data even when the GET fails, so catching its promise did not reliably handle refresh failure. The reset flow now explicitly awaits the fetch through mutate. A confirmed reset closes the dialog; failed refresh displays a separate success-with-refresh-failure message and a read-only retry. Successful list reads clear the refresh warning.
