# 作業分享教師名單：排除鎖定帳號與舊學年教師

## 問題及正式環境核對

2026-08-28 使用該校教師帳號讀取正式 `GET /api/v1/essay_assignments/share_options`，沒有新增或取消任何正式分享：

- 聖若瑟教區中學第五校本學年共 8 個教師帳號，包含 Excel 名單 7 位與另外追加的 1 個帳號。
- 分享選項應排除登入者本人，所以本次測試應返回 7 位。
- 正式接口實際返回 15 位，多出的 8 位沒有本學年的任教紀錄，其中 2 位已鎖定。
- 原因不是名單匯入失敗。分享服務原本會合併所有學年的任教資料，以及帳號上的直接學校關聯，未檢查帳號是否鎖定。
- 舊學年的任教紀錄保留 `active` 並不代表該老師今年仍在職，不能只檢查任教紀錄狀態。

## 本次修正

修改 `app/services/essay_assignment_share_service.rb`，新分享對象必須同時符合：

1. 屬於該校設定的目前學年，而不是全部歷年。
2. 該學年的任教狀態為 `active`。
3. 帳號角色為老師。
4. 帳號 `locked_at` 為空。
5. 不是分享者本人。
6. 儲存時仍需通過原本的作業類型權限檢查。

目前學年沿用 `School#current_academic_year`，依學校設定的啟用學年判斷，不另外改用今天日期。學校沒有設定目前學年時，不回退至舊學年的教師名單。

僅有相同 Email 網域、僅有帳號上的 `school_id`、或只在中文部任教，都不能代替本校目前學年的任教紀錄。

教師部門與職位也改讀目前學年，部門篩選只使用這次返回的可選教師資料，避免出現舊部門或已鎖定教師的部門。移除原本逐名教師查詢歷年職位的做法。

## 不能只在畫面隱藏

`PUT /api/v1/essay_assignments/:id/shares` 亦使用相同資格規則驗證新增對象。

- 直接傳入已鎖定老師的 ID 或 Email 都會拒絕。
- 只在舊學年任教、離職、調職或休假者不能新增為分享對象。
- 被取消的分享若重新加入，會重新檢查資格。
- 任一新增對象不合格時，先拒絕整個更新，不會先取消其他有效分享。

`share_options` 的 `teachers` 與 `options.teachers` 兩種返回格式保持一致，不需要修改前端 API 接法或重新設計 UI。

## 保留既有紀錄

- 不刪除老師帳號、舊學年任教資料、作業或歷史分享。
- 已存在的分享可以保留或由擁有人取消；本次不會因學年切換自動大量撤銷分享。
- 已分享的歷史對象可能仍出現在「已選取／已分享」區，方便擁有人管理；這不等於仍可在新增候選名單選取。
- 沒有修改 `same_school_teacher?` 的歷年學校關係判斷，避免影響已有作業派發及統計的授權邏輯。
- 沒有再鎖定或解鎖正式帳號，也沒有改密碼、班級或學生資料。

這是舊版正式接口的數值，不是新版本部署後的成果。回應只有約 5 KB，耗時主要發生在首個回應到達之前，不能以壓縮回應解決。尚未透過正式伺服器追蹤細分資料庫、認證、排隊及網絡各自耗時。

- 沒有加入後端教師名單快取；鎖定、解鎖及目前學年狀態變更仍在下次查詢即時反映。

### 前端改善

主要檔案：

- `src/app/components/essay/assignment/AssignmentCard.tsx`

行為：

## 再次複查：異常與安全邊界

2026-08-28 依使用者要求再次檢查，發現並修正以下風險：

1. 候選名單仍在重新核對時，舊選項原本仍可被點選。現在候選及原有分享兩個請求完成前都不可編輯。
2. 保存進行期間切換帳號、學校、學年或作業，舊回應可能更新新的視窗／快取。現在每次保存有獨立請求識別，範圍改變或元件卸載後忽略舊回應，不操作新視窗。
3. 連續快速點擊 Save 可能在狀態更新前送出兩次請求。現在除了停用按鈕，另有同步的進行中請求鎖。
4. HTTP 200 且 `success: true` 但沒有教師陣列，不能當成真的空名單。讀取時驗證陣列、唯一且非空的教師 ID、顯示欄位及部門格式；保存回應不完整也不當成已確認成功。
5. 後端分享名單讀取接口原先沒有啟用擁有人檢查。`index`、`sync`、舊 `share` 接口現在均只允許作業擁有人；其他教師即使知道作業 ID，也不能透過此接口讀取或管理分享名單。正常受分享老師仍可按原有權限讀取及編輯作業。
6. 原本缺少收件人欄位或 Email 查不到帳號，可能被當成取消全部分享。現在拒絕不完整欄位、非陣列、空白項目及找不到帳號的 Email，保留全部現有分享。
7. Rails 會把 JSON `[null]` 正規化為 `[]`。現在先驗證原始 JSON 收件人欄位，避免不合法內容被誤當成取消全部分享。

只有明確傳送 `teacher_ids: []`（或舊接口明確傳送 `teacher_emails: []`）才代表取消全部分享。Email 仍支援忽略大小寫、去除頭尾空白及重複項目。前端現有讀取／儲存格式不變。
